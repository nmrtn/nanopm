# What shipped — since the last update (2026-06-15)

A public changelog covering nanopm releases from **v0.11.0 to v0.26.0** (2026-06-15 → 2026-06-30), plus a preview of what's landing next. It's been a bigger stretch than usual: the memory system got rebuilt twice, the Opportunity → Solution loop closed end to end, and feedback capture was generalized beyond interviews.

---

## TL;DR

Sixteen releases landed. The headline arc: **memory** went from an ever-growing log → a compounding wiki → a leaner three-primitive engine (query → reasoning → ingest) that the rest of the pack now runs on. On top of that engine, the **Discover → Plan loop closed**: a ranked Opportunity database, a Solutions tree bridging opportunities to compared solutions, and planning skills that actually read both. **Feedback capture generalized** from interview-only to any source, with a durable raw archive. And still unreleased, in progress on a branch right now: **Supabase cloud sync** (multi-device / team sharing) and a **full-text search layer** wired into the wiki.

---

## 🧠 Memory rebuilt twice (v0.19–v0.22)

The append-only event log that every skill reloaded in full got replaced with a **maintained wiki** — the pattern from Karpathy's "LLM wiki." Each run now starts from a small, always-current index plus two consolidated briefs (company + current-work) instead of replaying the whole history.

- **v0.19.0** — the wiki schema (`NANOPM-WIKI.md`), three CLIs (ingest / confidence-gate / lint), and a one-time migration with zero content loss.
- **v0.20.0** — the ingest loop actually wired: five skills feed the wiki, held (low-confidence) writes surface for approval, a throttled lint pass keeps it honest.
- **v0.21.0** — **wiki-canonical**: every skill's *primary* output moves into the wiki (no more flat docs copied into it). PRDs, tasks, handoffs, opportunities, competitor intel — all live under `.nanopm/wiki/` now. `nanopm-export` renders any section to a shareable file on demand.
- **v0.22.0** — trimmed back to the model that inspired it: every skill re-expressed as a thin recipe over **query → reasoning → ingest**, the pre-write confidence gate removed (writes apply directly; a judgment lint surfaces contradictions after the fact instead of blocking before).

Net effect: sharper, cheaper runs that actually compound instead of drifting.

## 🔗 The Opportunity Solution Tree, end to end (v0.15–v0.18, v0.23–v0.24)

- **v0.15.0** — new `/pm-opportunities`: a ranked, agent-maintained database of user opportunities (Teresa Torres sense — problems, not solutions), bridging Discover and Plan.
- **v0.16.0–v0.18.0** — the viewer gets a real home for it (ranked sortable table, detail pages), then a way to *grow* it without a terminal (Add ▾ menu, a reusable dedup subagent, an additive `generate` mode).
- **v0.23.0** — the loop closes: `pm-objectives`, `pm-strategy`, `pm-roadmap`, and `pm-discovery` now actually *read* the ranked opportunities when deciding what to build, not just feedback themes.
- **v0.24.0** — the tree's missing node: new `/pm-solutions` convenes three expert lenses (Eng / Design / Business) concurrently to propose *competing* solutions for one opportunity, converges them into ≥3 framed options with pitch, appetite, riskiest assumption, and a dissent note. The founder shortlists — the agent never auto-chooses.

Chain is now real: `pm-opportunities → pm-solutions → pm-prd`.

## 📥 Feedback becomes a first-class substrate (v0.25–v0.26)

- **v0.25.0** — every wiki page write now leaves a heartbeat in the global log (`nanopm_wiki_doc_log`), wired into all 17 doc-writing skills plus the two entity skills. The log was the memory's primary "is this working" surface but had gone quiet for anyone not running the bookkeeping subagents directly.
- **v0.26.0** — `/pm-interview` retired; replaced by **`/pm-add-feedback`**, which accepts a feedback from *any* source (interview, support ticket, sales call, review, a hallway comment), archives the **raw** input verbatim before extraction, and grounds opportunities in the actual words used. Interview *prep* moved to `/pm-discovery`, where it belongs (a discovery activity, not a capture one).

## 💬 New Daily Ops surface + sharper build skills

- **`/pm-brainstorm` (v0.13.0)** — an informal, context-loaded jam with Nano (the expert CPO persona), no gate, no PRD. Resumable via your host's native session picker; read-only by construction (`Bash`/`Edit`/`Write` denied).
- **Plan Brief (v0.14.0)** — a `PLAN-SUMMARY.md` counterpart to the Context Brief: what you're betting on, aiming for, building now, saying no to — regenerated after every Plan skill, loaded into every run.
- **`pm-breakdown` (v0.17.0)** — decomposition now identifies a shared Wave 0 foundation, splits the rest into collision-free parallel waves, and writes the Build Plan back into the source PRD.
- **`pm-prd` (v0.12.2)** — Phase 2 fans out one retrieval subagent per present doc instead of reading everything into context; Phase 4b adds a 4-lens advisory review panel alongside the hard falsifiability gate.

## 🖥 Viewer + plumbing

- One consistent `ActionButton` for Run / Refresh / Reasoning across every screen (v0.12.2).
- Company-tier shared docs — vision/business-model/org can live once and symlink across a company's repos (v0.11.0); per-project config stops leaking across unrelated projects (v0.11.0).
- One-click skill-pack updates from inside the viewer, maintainer-guarded against overwriting a dev clone (v0.11.1).

## 🔜 In progress, not yet released

Two things landing next, both still on a branch (`VERSION` hasn't bumped past 0.26.0 yet):

- **Supabase cloud sync** — push/pull the wiki to a shared backend so a team (or you across machines) stays in sync: remote-status checks, a pull-direction badge, content-hash tracking to protect hand-edits, auto-push after skill runs, and a sync-status badge in the viewer sidebar. Several rounds of adversarial review already landed (path-traversal guards, null-content handling, credential hardening) before this ships.
- **Full-text search** — a SQLite FTS5 layer over the wiki, now wired into `pm-data`, `pm-retro`, and `pm-challenge-me` so queries stop relying on the catalog alone.
- Also on the branch: the wiki + raw archive are now tracked in git for team sharing, and company-tier symlink sharing is being deprecated in favor of the plain wiki/docs model.
